Case Study · Cloud Infrastructure / Analytics / Operational Delivery

From professional portfolio to measurable recruiting platform.

Building a website is one thing. Making it observable, measurable, privacy-conscious and useful for business decisions is another. This project connected static-site delivery, document distribution, campaign attribution and event reporting into a lightweight operational system.

All Case StudiesInspect GitHub Repository

Business objective

Determine whether outreach creates meaningful engagement.

The professional portfolio needed to support a targeted job-search strategy—not simply display a résumé. The core questions were practical: Which channels bring visitors? What material do visitors explore? Are recruiter campaign links being used? Do visitors click to download the résumé or executive impact sheet? And can these measurements work without attempting to identify individual visitors?

Deliver the content

Host a professional portfolio, leadership case studies and downloadable recruiter documents with static-site deployment through Cloudflare Pages and GitHub.

Measure the journey

Capture pageviews, document-download clicks, contact and outbound interactions, and campaign-tagged arrivals.

Respect consent

Use an Analytics purpose in Cloudflare Zaraz Consent Management to gate GA4 reporting based on visitor choice.

Architecture

Keep the website fast; make measurement explicit.

Source & delivery

GitHub repository → Cloudflare Pages → public static site, downloadable PDFs and a small shared JavaScript event module.

Traffic & engagement

Cloudflare Web Analytics for site-level traffic, alongside Cloudflare Zaraz forwarding pageviews and custom engagement events to Google Analytics 4.

Attribution & reporting

Allowlisted UTM campaign parameters, named events, and an event-scoped GA4 custom dimension (`kind`) to distinguish résumé and impact-sheet clicks.

The event module uses explicit names such as portfolio_document_download, portfolio_campaign_landing, portfolio_contact_click and portfolio_outbound_click. Events represent observed clicks or arrivals—not proof that a file was read, a contact was completed, or a recruiter was identified.

Implementation and validation

Instrument, test, diagnose, verify.

1. Event instrumentation

Deployed shared site-wide code for document and outbound-link interactions, plus campaign landing events with constrained source, medium and campaign values.

2. Consent configuration

Configured the Zaraz Analytics purpose, verified consent acceptance and rejection state, and checked traffic behavior during privacy tests.

3. End-to-end testing

Confirmed pageviews, a custom document-download event and campaign-attribution events in GA4. Initial Realtime delays were diagnosed before concluding delivery had failed.

Verified outcome

Reporting works; business impact still requires time.

The project reached a functioning two-level analytics setup: Cloudflare Web Analytics displayed site traffic, and GA4 received pageviews and custom events via Zaraz. Campaign events were confirmed after reporting latency, and the site owner verified PDF access and consent choices. The website now has the instrumentation to evaluate recruiting outreach over time.

Measurement boundaries: There are no asserted increases in recruiter responses, hiring outcomes, conversion rates, or identified visitors. A separate automatic file_download event was not observed during final checks; we use the named custom download event for this workflow. Any future effectiveness claims should be supported by sufficient production data.

Leadership takeaway

Turn a communications asset into an observable system.

The value was in connecting an operational need to straightforward architecture, controlled implementation, source-managed deployment, repeatable validation and trustworthy reporting. The same method applies to service operations, customer-facing platforms and automation programs: define what matters, capture evidence, respect constraints and improve from real signals.
